Slide 01

Abstract

The Enterprise IT & Corporate Facilities Service Portal is an AI-powered web application that streamlines IT support and facility management within an organization.

Employees submit requests in plain English, which are automatically classified using NLP models (DistilBERT & RoBERTa) and routed to the right specialist team.

The portal supports three user roles — Admin, Employee, and Technician — with real-time SLA timers, emergency SOS telephony, a self-service knowledge base, and executive analytics.

Built with HTML/CSS/JS on the frontend and Python FastAPI with PostgreSQL on the backend, developed across 12 modules by a 2-person team.

Slide 03

Existing System

The conventional service desk and facilities management model relies heavily on manual work:

  • Manual Classification: Tickets are sorted and routed by staff manually, causing delays.
  • Disconnected Systems: IT tickets, facility requests, and SOS calls use separate tools.
  • No Real-time SLA Trackers: Technicians lack visual cues for active SLA resolution deadlines.
  • Siloed Communications: Users must make direct calls or check emails continuously for updates.
Slide 04

Problem Statement

Legacy IT and facility request systems in organizations create operational bottlenecks:

  • High Response Time: Manual routing introduces delay and increases Mean Time to Resolve (MTTR).
  • Human Error: Over 30% of manual tickets are initially sent to incorrect technician teams.
  • Unmonitored Deadlines: Technicians miss SLA timelines due to a lack of live alerts and countdowns.
  • No Self-Service Help: Simple repetitive problems overload helpdesk queues without automation.
Slide 05

Proposed System

We propose a unified, AI-powered service portal featuring three role-specific workspaces:

  • Real-time AI NLP Triage: DistilBERT classifies the category, and RoBERTa predicts sentiment/urgency on-the-fly.
  • Live SLA Countdown Display: Every ticket shows a ticking visual countdown based on priority (P1=2h, P2=8h, P3=24h).
  • SOS Dialing and Email Alerts: Immediate telephony trigger via the browser, combined with automated email dispatch to the Admin.
  • Permanent Storage Layer: A single FastAPI backend storing system transactions in a relational PostgreSQL database.
Slide 06

Modules Description

The application is built across 12 independent modules, developed incrementally week-by-week:

  • M1-M3: Core Service Desk — Glassmorphism UI layout, 2FA email authentication, and base ticket routing engine.
  • M4-M5: Communications & AI — Emergency SOS telephony trigger and live Hugging Face NLP triage endpoint.
  • M6-M7: Deflection & ITAM — Knowledge Base deflectors and IT Asset Catalog lifecycle tracking.
  • M8-M9: Crises & Charts — Major Incidents war room dashboard and visual SLA performance CSS charts.
  • M10-M12: Governance & Polish — Change approvals, peer-to-peer chat, dark/light themes, and security audit logs.

➔

Software & Hardware Requirements

Software Requirements

  • Frontend: HTML5, CSS3, JavaScript
  • Backend: Python FastAPI + PostgreSQL + SQLAlchemy
  • AI Models: Hugging Face (DistilBERT + RoBERTa)
  • Email API: FormSubmit.co (2FA OTP & SOS alerts)
  • IDE: Eclipse IDE | Browser — Chrome / Edge

Hardware Requirements

  • Processor: Intel Core i3 or above
  • RAM: Minimum 4 GB (8 GB recommended)
  • Storage: Minimum 2 GB free disk space
  • OS: Windows 10/11, macOS, or Linux with internet connection
