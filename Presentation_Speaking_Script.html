Presentation Speaking Script

Enterprise IT & Corporate Facilities Service Portal
Presenter: Sam Antrose A H (Teammate: Saraswathi E) | 18 August 2026
How to use this script: Below is a slide-by-slide guide for your presentation. Each slide has an Opening Sentence (what to say first) and a set of Key Points (the details to explain).

Slide 1: Title Slide

"Good morning everyone. I'm Sam Antrose, and my teammate is Saraswathi. We are presenting our project — Enterprise IT & Corporate Facilities Service Portal."
  • This project is a unified, intelligent system designed to coordinate both IT support and corporate facilities issues under one single interface.

Slide 2: Abstract

"Our project is an AI-powered web application for managing IT support and facility maintenance in an organization."
  • Natural Language Input: Employees can type their issues in plain, everyday English.
  • AI-Powered Triage: The system automatically classifies the request's category and priority using Hugging Face NLP models (DistilBERT & RoBERTa).
  • Automatic Routing: Tickets are auto-routed directly to the appropriate specialist team (Hardware, Software, Facilities, or Network).
  • Tech Stack: Built on a modern, decoupled architecture using HTML, CSS, JavaScript on the frontend, and Python FastAPI with PostgreSQL on the backend.

Slide 3: Objectives

"Our primary goals are focused on automation, efficiency, and real-time oversight."
  • Automate Routing: We automate ticket classification to completely bypass manual triage bottlenecks.
  • SLA Enforcements: We show ticking timers directly inside queues to enforce deadlines for critical issues.
  • Urgency Response: Telephony dialers and admin alerts dispatch for high-risk P1 facilities crises.
  • Deflect Tickets: Self-service articles prompt matches dynamically to reduce recurring ticket queues.

Slide 4: Existing System

"Let us examine how service tickets are managed currently."
  • Manual Sorting: Triage staff have to read, categorize, and route incoming requests manually, creating massive bottlenecks.
  • Fragmented Systems: Facility maintenance, IT requests, and emergency contacts are scattered across disconnected spreadsheets and emails.
  • Missing deadliness: Support groups cannot easily track resolution deadlines in real-time.
  • Zero Self-Help: Repetitive calls for simple issues flood service desks without automated search suggestions.

Slide 5: Problem Statement

"This manual system creates major operational issues for enterprises."
  • High Response Time (MTTR): Delayed assignments directly lead to long resolution cycles.
  • Human Routing Errors: Up to 30% of manual request tickets are sent to wrong specialist technician queues.
  • Unmonitored SLA Breaches: No automated countdown notifications mean deadlines are repeatedly missed.
  • High Operations Cost: Dedicating full-time staff to manual ticket sorting raises overhead.

Slide 6: Proposed System

"To address these issues, we designed a unified, intelligent service portal."
  • NLP AI Core: Live text analysis loads DistilBERT & RoBERTa models as the user types.
  • Visual Countdowns: SLA timers show technicians exact resolution timelines (P1=2h, P2=8h, P3=24h).
  • SOS Email & Telephony: One-click trigger runs voice dialer and dispatches alert emails to the admin simultaneously.
  • Central DB Persistence: Relational PostgreSQL storage tracks all users, tickets, and logs via SQLAlchemy.

Slide 7: Modules Description

"The platform was built across 12 distinct weekly milestones."
  • M1-M3: Front-end glassmorphism design system, 2FA secure email OTP verification, and basic ticketing engine.
  • M4-M5: Integration of emergency SOS telephony links and backend Hugging Face AI FastAPI endpoints.
  • M6-M7: Deflector deflection rules via KB articles, and IT Asset registry lifecycle tracker.
  • M8-M9: Major Incident dashboard workspace, and pure CSS SLA performance progress charts.
  • M10-M12: Change management workflow, peer-to-peer ticket chat, dark theme, and audit logging.

Slide 8: Data Flow Diagram (DFD)

"Here is how request data flows from the user to database resolution."
  • User Input: Request starts when an employee submits details in the web form.
  • AI processing: The FastAPI backend queries NLP models to set category, priority, and vendor.
  • Database Write: Structured details are written to PostgreSQL tables via SQLAlchemy ORM.
  • Technician update: Technician works on active queues, resolving the ticket and logging audit events.

Slide 9: System Workflow

"Here is the step-by-step processing workflow of an incident."
  • Submission & Triage: User enters the ticket, AI classifies details, routes to vendor, and SLA starts.
  • Queue Work: Technician claims ticket, works on the issues, and collaborates via chat modal.
  • Resolution & Logging: SLA stops, ticket status changes, and a permanent security audit record is written.

Slide 10: Requirements

"These are the software and hardware requirements needed to deploy the portal."
  • Software: HTML/CSS/JS frontend, Python FastAPI + Uvicorn backend, PostgreSQL DB, SQLAlchemy ORM, and Hugging Face AI.
  • Hardware: Minimum Intel Core i3 (i5 recommended for local AI load), 4GB RAM (8GB recommended), and active internet.

Slide 11: Thank You

"Thank you for your time. I am now open to any questions."
  • Be ready to explain PostgreSQL setup, FastAPI routing, or Hugging Face token categorization if asked by the panel.
